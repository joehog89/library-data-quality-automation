Pipeline -> A recipe - it does nothing until something runs..
stages -> jobs -> steps
RUN -> execution of the pipeline, every push makes a new run (it should have its own log, id, etc)
AGENT -> (env) where the to carry out instructions, either self-hosted or defaulted with Microsoft
TRIGGER -> condition used to run, e.g. push, pull, etc
STAGE -> phase of work in the PL, e.g. build, deploy, stages run seqencetially by default
JOB -> unit of work inside a stage, one job runs one agent, this means everything in a job shares the env/folders, etc
STEP -> unit of work inside a job, a step could be a task or a script, something that runs top/bottom
SCRIPT -> a bunch of cli, e.g pytest -m pytest, GitHub actions (run), etc
TASK -> a step that calls a prebuilt unit of work, (think actions) PublishTestResults@2, has the ability to take
named input, this is instead of cli seen in scripts, careful updates can break a PL overnight
ARTEFACT -> typically a handover, file produced at the end of a agents workload
ENVIRONMENT -> target to deploy, prod, test, etc
